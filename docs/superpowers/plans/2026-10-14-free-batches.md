# 무료 Worker의 큰 요청 분할

사용자가 큰 작업의 요청 분할을 선택했다. 기존 100개 키, 값별 64 KiB, 가져오기 128 KiB, 백업 1 MiB 한도와 최종 원자적 반영을 유지한다. 현재 단일 큰 요청은 실제 CPU 10ms를 반복 초과했다.

Kind: normative | Audience: 구현·검증 작업자 | Purpose: 큰 작업을 작은 인증된 요청으로 나누고 무료 한도에서 검증한다 | Non-goals: 유료 플랜 전환, 원문·토큰 로그, 가져오기 일부 반영.

## 설계

- 조회는 요청당 최대 10개와 암호문 합계 약 64 KiB로 제한한다. CLI는 10개씩 조회하고 서버의 분할 요구에 따라 더 나눈다. 전체 값 검증이 끝난 뒤에만 자식 프로그램을 실행한다. CI 정책은 각 요청마다 다시 확인한다.
- 작은 가져오기·복구·백업은 기존 API를 유지한다. 큰 요청은 고정 코드 `chunk_required`로 분할 경로를 요구한다.
- D1 `staged_operations`와 `staged_chunks`에 임시 작업을 둔다. 가져오기 준비 단계에는 암호문과 CAS 메타데이터만 저장하며 원문을 저장하지 않는다. 복구 준비 단계도 백업의 암호문과 메타데이터만 저장한다.
- 작업은 10분 후 만료하며 동시에 최대 8개를 허용한다. 업로드 순서와 개수·바이트 상한을 검증한다. 준비 실패와 만료 시 운영 데이터를 변경하지 않는다.
- 최종 가져오기 반영은 D1의 한 배치에서 CAS를 다시 검증하고 모든 버전을 반영한다. 복구는 빈 대상 검사, 참조·시간·버전 개수 검사, 정책 비활성과 전체 삽입을 한 배치에서 수행한다. 최종 반영 재요청은 완료된 작업을 다시 반영하지 않는다.
- 큰 백업은 D1의 한 배치에서 암호문 행을 임시 작업으로 복사해 일관된 스냅샷을 만든 뒤, 작은 페이지로 받는다. 전체 백업 크기와 행 개수 검증 후에만 파일을 만든다.
- 모든 준비·페이지·반영 API는 기존 본인 Google Access 인증과 동일 출처 검사를 유지한다. CI에는 읽기 분할만 추가한다.
- UI에는 큰 작업의 진행 상태만 보여 준다. 서버 세션·테이블 등 구현 세부 사항을 사용자 흐름에 노출하지 않는다.

## 구현 순서와 검증

1. `migrations/0002_staged_operations.sql`, `src/shared/operations.ts`: 임시 작업과 만료, 개수·바이트 제한, 순서 검사. `tests/operations.test.ts`에서 준비 중 원문·실제 시크릿 미저장, 만료·초과·잘못된 순서 거부를 확인한다.
2. `src/shared/store.ts`, `src/shared/backup.ts`: 작은 경로의 분할 요구, 가져오기 암호문 준비와 SQL 원자적 반영, 작은 단위의 복구 검증과 스냅샷 백업. 중간 실패·stale CAS·기존 복구 대상·깨진 참조에서 전체 롤백을 검사한다.
3. `src/admin/index.ts`: 작업 생성·청크·최종 반영·백업 페이지 API. 무인증·잘못된 Origin과 임의 필드 요청을 거부하고 감사에 본문을 기록하지 않는 API 테스트를 추가한다.
4. `src/cli/client.ts`, `public/app.js`: 조회와 큰 관리 작업 분할. 뒤 청크가 실패하면 자식 프로그램이나 부분 저장을 실행하지 않는 회귀 테스트를 추가한다. 작은 요청의 기존 동작도 유지한다.
5. 전체 타입 검사·테스트·빌드, 독립 코드 리뷰, 두 Worker dry-run. 운영·복구 D1에 마이그레이션 적용 후 무료 CPU를 실시간 tail의 메타데이터만으로 측정한다.
6. 본인 웹/CLI, 실제 Actions, 빈 D1 복구, Cron 삭제를 새 구현으로 확인한다. 임시 워크플로·합성 데이터·복구 Worker/DB를 정리하고 운영 문서와 main을 갱신한다.

## 검토 중점

- 최종 반영 전에는 다른 조회에 준비 데이터가 나타나지 않는다.
- 한 청크가 변조되거나 순서가 바뀌면 최종 반영을 거부한다.
- 최종 CAS 실패나 복구의 참조 위반으로 모든 삽입을 롤백한다.
- 완료 재요청, 중간 취소, 만료, 동시 준비 요청이 중복 저장을 만들지 않는다.
- 여러 64 KiB 파일 조회의 분할 후에도 BOM·CRLF·정확한 바이트를 보존한다.
- 로그·임시 작업·공개 빌드에는 원문과 인증 토큰을 저장하지 않는다.
