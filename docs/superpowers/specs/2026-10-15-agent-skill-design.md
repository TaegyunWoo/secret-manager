# 로컬 에이전트용 시크릿 관리 설계

이 설계는 개인 프로젝트를 구축하는 로컬 코딩 에이전트가 시크릿 생성·등록부터 프로젝트 실행 연결까지 수행하도록 스킬과 관리 CLI를 확장한다. 사용자는 저장소 소유자 한 명이다. 구현할 동작과 범위를 정의하며 승인 근거는 [승인 기록](../../approvals.md)에 남긴다.

## 목표와 범위

에이전트는 프로젝트에 필요한 시크릿을 파악하고, 저장소의 프로젝트·환경을 준비한 뒤 값을 등록한다. 대상 프로젝트에는 비밀값 없는 연결 설정과 실행 명령을 남긴다. 실행 시 `psm run`이 필요한 값만 자식 프로세스에 전달한다.

사용자가 합의한 범위는 프로젝트·환경·시크릿의 조회·생성·수정·삭제, `.env` 일괄 가져오기, 로컬 실행 연결이다. 이력 복원, 백업 복구, CI 권한 관리 명령은 후속 범위다. 원격 에이전트, 팀 사용자, 외부 서비스 가입·결제·키 발급 자동화도 이번 범위에서 제외한다.

기존 관리 API와 본인 로그인 세션을 사용한다. 별도의 에이전트 토큰이나 서버 권한 체계는 추가하지 않는다. 관리 작업에 필요한 서버 API는 이미 있으므로 클라이언트와 스킬의 확장을 기본으로 한다.

## 현재 구현의 근거

아래 항목은 저장소에서 확인한 현재 동작이다. 이후 절은 구현할 요구사항이다.

- [관리 라우터](../../../src/admin/index.ts)는 프로젝트·환경·시크릿 관리와 가져오기 API를 제공한다. 요청 계약은 [API 참조](../../api.md)가 소유한다.
- [Access 인증](../../../src/shared/auth.ts)의 `verifyAccess`는 관리자 이메일이 일치하는 JWT만 허용한다. 인증한 모든 호출자는 같은 관리자 권한을 갖는다.
- [CLI 진입점](../../../src/cli/index.ts)은 `login`과 `run`만 제공한다. [설정 로더](../../../src/cli/config.ts)는 로그인에도 시크릿 매핑을 요구한다.
- [실행 모듈](../../../src/cli/run.ts)은 환경변수와 임시 파일 경로를 자식 프로세스에 주입한다. [조회 클라이언트](../../../src/cli/client.ts)는 모든 값을 검증한 뒤 실행을 허용한다.
- [가져오기 파서](../../../src/shared/imports.ts)는 `.env`를 셸 평가나 변수 치환 없이 처리한다. [저장 모듈](../../../src/shared/store.ts)의 가져오기는 기존 파일 시크릿을 덮어쓸 때도 종류를 `env`로 변경한다.

## 스킬과 CLI의 역할

스킬은 저장소의 `skills/personal-secret-manager/SKILL.md`에서 관리한다. 개인 프로젝트의 비밀키, 환경변수, PEM, 시크릿 저장소 연결 작업을 설명에 명시한다. 에이전트가 스킬을 선택하면 대상 파악, 메타데이터 확인, 등록, 프로젝트 연결, 검증 순서로 작업한다.

관리 CLI는 인증, 입력 파일 읽기, API 호출, 응답 검증과 오류 처리를 담당한다. 스킬은 관리 작업에 CLI를 사용한다. 셸 명령 안에 비밀값을 직접 넣는 호출 예시는 제공하지 않는다.

CLI는 프로젝트·환경의 목록·생성·수정·삭제와 시크릿의 목록·신규 등록·수정·삭제를 지원한다. `.env` 가져오기는 미리보기와 선택한 항목 적용을 지원한다. 초기 연결 명령은 프로젝트 설정이 없는 디렉터리에서도 동작한다. 원문 출력, 백업, 복원, CI 정책용 명령은 제공하지 않는다.

관리 명령은 비밀값 없는 JSON 결과를 stdout에 출력한다. 목록, 생성 결과, 충돌 정보와 가져오기 미리보기에도 값과 인증 토큰을 포함하지 않는다. 오류는 안정적인 코드와 종료 상태로 구분하며 서버의 임의 응답 본문을 그대로 출력하지 않는다. 기존 `run`의 자식 프로세스 표준 입출력과 종료 코드 전달은 유지한다.

## 설치와 초기 연결

CLI는 이 저장소에서 빌드하고 로컬에서 설치한다. 스킬은 사용자 공통 스킬 디렉터리에 설치해 다른 개인 프로젝트에서도 사용할 수 있게 한다. 설치 도구는 선택한 대상과 설치할 파일을 보여준다. 기존에 다른 내용의 스킬이 있으면 자동으로 덮어쓰지 않는다.

관리 서버 주소는 비밀값 없는 사용자 공통 설정에 저장할 수 있게 한다. 사용자가 지정한 서버 주소, 프로젝트 설정, 사용자 공통 설정 순으로 사용할 주소를 결정한다. 설정이 없으면 주소 입력 방법을 안내한다. 임의의 서버 주소를 자동으로 신뢰하지 않는다.

로그인은 시크릿 매핑과 프로젝트 연결 없이 가능해야 한다. CLI는 기존 cloudflared 로그인과 토큰 조회를 재사용하고 토큰을 출력하지 않는다. 인증이 만료되면 로그인 필요 상태를 반환한다. 스킬은 본인의 재로그인이 필요한 상황을 안내한다.

프로젝트 초기화는 기존 `psm.json`이 있으면 그 연결을 우선한다. 연결이 없으면 Git 저장소 루트의 디렉터리 이름으로 프로젝트 이름과 slug를 도출한다. Git 저장소가 아니면 현재 디렉터리 이름을 사용한다. 기본 환경은 `dev`다. 유효한 slug를 만들 수 없으면 이름을 사용자에게 요청한다.

같은 slug의 원격 프로젝트가 없으면 프로젝트와 `dev` 환경을 생성한다. 미연결 디렉터리에서 같은 slug의 프로젝트를 발견하면 재사용 여부를 확인한다. 거부된 경우 다른 slug를 요청한다. 이름 충돌을 피하려고 임의의 기존 프로젝트를 선택하지 않는다.

연결 파일에는 서버 주소, 프로젝트·환경 연결 정보, 시크릿 이름과 전달 방식만 저장한다. 원격 자원의 식별자를 확인해 이름이 바뀌거나 대상이 사라졌을 때 다른 자원으로 자동 연결되지 않게 한다. 정확한 JSON 필드와 조회 방식은 구현자가 정한다.

기존 형식의 `psm.json`과 명시적인 `psm run --project ... --env ...` 호출은 계속 지원한다. 새 연결 정보는 기본 실행 대상을 제공하되 명시적인 대상 선택을 허용한다. 관리 변경의 실제 대상은 실행 전에 JSON 메타데이터로 확인할 수 있어야 한다.

## 비밀값 준비와 입력

로컬에서 만들 수 있는 랜덤 시크릿과 암호키는 프로젝트가 요구하는 형식으로 생성한다. 외부 서비스가 발급해야 하는 API 키를 랜덤 문자열로 대체하지 않는다. 외부 발급값은 사용자가 제공하거나 이미 허용된 도구로 받은 값을 사용한다.

입력은 기존 `.env`, UTF-8 파일, 이름을 지정한 로컬 환경변수, stdin을 지원한다. 원문을 명령 인자로 받는 옵션은 만들지 않는다. CLI가 파일이나 환경변수를 직접 읽어 API로 전달하고 에이전트에는 결과 메타데이터만 반환한다.

스킬은 먼저 필요한 키 이름과 입력 출처를 결정한다. 관련 없는 파일이나 환경변수에서 비밀값을 탐색하지 않는다. 필요한 값이 없으면 키 이름과 입력 방법을 안내하고 해당 연동을 대기 상태로 남긴다. 가짜 값으로 성공을 보고하지 않는다.

일반 값은 `env`, 파일로 전달할 값은 `file`로 등록한다. 파일 입력은 기존 제한 안에서 UTF-8 원문과 줄바꿈을 보존한다. 가져오기에는 기존 파서를 사용하며 입력을 셸에서 실행하지 않는다.

대화·CLI 출력·설정 파일에 비밀값을 새로 노출하지 않는 것을 작업 규칙으로 삼는다. 에이전트가 이미 받은 값이나 자식 프로그램이 출력한 값까지 숨길 수 있다고 보장하지 않는다. 입력으로 받은 원본 파일은 자동 삭제하지 않는다.

## 자동 작업과 확인

새 프로젝트·환경 생성, 새 시크릿 등록, 대상 프로젝트의 연결 설정 작성과 실행 검증은 자동으로 진행한다. 이미 등록된 키는 메타데이터로 확인해 사용할 수 있다. 사용자가 새 값을 제공한 경우에는 기존 값과 같다고 추정하지 않는다.

기존 시크릿의 값·이름·종류 변경과 모든 삭제는 사용자 확인 후 실행한다. 프로젝트·환경의 기존 이름이나 연결 대상을 바꾸는 작업도 확인 대상이다. 확인에는 대상 프로젝트·환경, 키 이름, 변경 종류를 표시하고 비밀값은 표시하지 않는다.

CLI는 신규 등록과 기존 항목 수정을 구분한다. 자동 upsert는 제공하지 않는다. 기존 항목 수정·삭제에는 명시적인 확인 옵션을 요구하고, 스킬은 대화에서 확인받은 뒤에만 그 옵션을 사용한다. 이 옵션은 사람의 신원을 증명하지 않으며 서버의 권한 제한을 대신하지 않는다.

시크릿 수정·삭제는 확인한 버전 ID를 사용한다. 버전 충돌이 발생하면 최신 메타데이터를 다시 읽고 변경 내용을 확인받는다. 오래된 확인을 근거로 최신 버전을 자동 덮어쓰지 않는다. 프로젝트·환경 삭제는 기존 API의 하위 자원 제한을 유지하고 연쇄 삭제를 추가하지 않는다.

`.env` 미리보기는 키 이름, 신규·기존 상태, 종류 변경과 충돌 여부만 반환한다. 새 항목은 자동 적용할 수 있다. 기존 항목은 사용자가 승인한 항목만 선택해 적용한다. `file`에서 `env`로 바뀌는 항목은 확인에 종류 변경을 명시한다.

가져오기에는 기존 크기 제한과 분할 작업 API를 적용한다. 선택한 항목은 기존 API의 원자적 적용과 버전 검사를 유지한다. 서버의 가져오기 미리보기에 포함된 원문은 CLI가 출력 전에 제거한다.

## 프로젝트 연결과 완료 기준

스킬은 대상 프로젝트가 실제로 요구하는 환경변수 이름과 파일 경로 변수를 파악한다. `psm.json`에 필요한 키만 매핑하고 일반 값은 자식 환경변수로 전달한다. PEM 등은 기존 실행 모듈이 만든 임시 파일 경로로 전달한다.

프로젝트의 실행 스크립트나 개발 문서에는 `psm run`을 사용하는 명령을 남긴다. 애플리케이션이 환경변수를 읽을 수 있도록 필요한 연결 코드를 작성할 수 있다. 평문 `.env` 생성은 사용자가 별도로 선택한 경우에만 수행한다. 입력 파일의 Git 제외 여부를 확인하고 필요한 제외 규칙을 추가하되 기존 파일을 자동 삭제하지 않는다.

검증은 비밀값을 출력하지 않는 주입 확인과 대상 프로젝트의 실행 또는 설정 검증으로 구성한다. 가능한 경우 프로젝트의 기존 테스트나 상태 확인을 사용한다. 외부 API 키의 유효성이 별도로 확인되지 않았으면 그 한계를 완료 보고에 적는다.

성공 보고에는 원격 프로젝트·환경, 등록하거나 재사용한 키 이름, 변경한 프로젝트 파일, 실행 명령과 검증 결과를 포함한다. 인증 실패, 키 누락, 등록 실패 또는 프로젝트 연결 실패가 있으면 전체 연동 완료로 보고하지 않는다. 완료된 단계와 남은 단계를 구분해 다시 시작할 수 있게 한다.

## 오류와 재시도

CLI는 인증 필요, 대상 없음, 이름·버전 충돌, 확인 필요, 입력 오류, 연결 실패를 구분한다. 관리 명령은 성공하지 않은 작업을 성공 JSON으로 반환하지 않는다. 서버 요청과 응답 크기 제한은 기존 계약을 유지한다.

변경 요청의 응답이 불확실하면 먼저 메타데이터를 다시 조회한다. 새 프로젝트·환경·시크릿이 이미 만들어졌을 가능성을 확인한 뒤 후속 행동을 결정한다. 확인만으로 결과를 판단할 수 없는 값 변경은 자동 재전송하지 않는다.

초기화와 등록이 여러 단계에 걸쳐 일부만 성공해도 이미 만든 자원을 자동 삭제하지 않는다. 재실행은 연결과 기존 메타데이터를 확인해 이어간다. 기존 키가 발견되면 신규 생성으로 재시도하거나 값을 바꾸지 않는다.

## 구현자가 정할 세부 사항

다음 선택은 사용자 합의가 아니라 설계 작성자의 제안이다. 구현 계획에서 기존 코드에 맞춰 구체화한다.

- 명령 이름과 옵션, JSON 결과 필드, 종료 코드의 상세 체계.
- 사용자 공통 설정 파일 경로와 스킬 설치 명령. 설치 대상은 명시적으로 선택할 수 있어야 한다.
- 프로젝트 연결 정보를 나타내는 JSON 필드와 기존 형식 호환 방식.
- 로컬 키 생성에 사용하는 기존 실행 도구와 라이브러리. 요구 형식이 명확한 경우에만 생성한다.
- CLI 내부 모듈 분리와 테스트용 API·인증 대체 수단. 운영 인증을 우회하는 모드는 추가하지 않는다.

## 수용 기준과 검증

1. `psm.json`과 시크릿 매핑이 없는 새 프로젝트에서 로그인과 초기 연결을 시작할 수 있다.
2. 신규 프로젝트·`dev` 환경·시크릿을 만들고 비밀값 없는 연결 설정을 작성할 수 있다.
3. `.env`, 환경변수, stdin과 파일 입력을 등록하며 관리 stdout·stderr에 원문이나 토큰이 나오지 않는다.
4. 기존 키 변경·삭제는 확인 옵션 없이는 실패하며 버전 충돌을 자동으로 덮어쓰지 않는다.
5. 가져오기 미리보기에서 원문을 숨기고 기존 항목과 종류 변경을 구분한다. 승인한 항목만 원자적으로 적용한다.
6. 재실행에서 기존 연결을 재사용하며 모호한 프로젝트를 자동 선택하지 않는다. 불확실한 쓰기를 자동 반복하지 않는다.
7. 기존 `login`·`run` 호출, CI 조회, 임시 파일 권한·정리와 자식 종료 코드 전달이 유지된다.
8. 생성한 합성 비밀값으로 프로젝트 실행 연결을 검증한다. 설치한 스킬이 다른 프로젝트에서도 찾을 수 있는지 확인한다.

자동 검증에는 새 CLI의 로컬 API 통합 테스트와 기존 `npm run check`를 사용한다. 서버 변경이 필요하면 관련 Worker 검증도 수행한다. 실제 계정 로그인, 사용자 공통 설치와 실제 프로젝트 연결은 로컬 합성 테스트와 구분해 결과를 기록한다.
